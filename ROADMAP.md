# Roadmap

This roadmap communicates direction, not a fixed commitment. Priorities may change as the product and its users become better understood.

## 1. Product and governance foundation

- Define the product vision, target users, and primary use cases.
- Confirm whether the project remains proprietary or adopts an open-source license.
- Select and document the application architecture and technology stack.
- Establish the issue, pull request, decision-record, and Project workflows.
- Add real continuous integration checks and prove their failure paths.
- Upgrade the GitHub plan or change visibility so `main` can be technically protected.
- Document security, privacy, data-retention, and recovery requirements.

## 2. Initial product

- Define the smallest end-to-end user journey.
- Build the initial domain and data models.
- Implement authentication and authorization, if required.
- Deliver the first usable workflow with automated test coverage.
- Add accessibility, observability, and operational baselines.

## 3. Safe delivery

- Establish staging and production environments.
- Use short-lived deployment credentials and record the deployed commit.
- Add post-deployment verification and a tested rollback runbook.
- Introduce generated releases and changelogs only after release automation is proven.

## 4. Validation and growth

- Gather structured feedback from early users.
- Improve accessibility, reliability, security, and performance.
- Define release, deployment, and rollback processes.
- Prioritize integrations and expanded workflows based on validated needs.

Actionable work belongs in GitHub Issues and the [Candidait Project](https://github.com/users/sjtechrec/projects/2). This roadmap communicates direction without duplicating live status.
